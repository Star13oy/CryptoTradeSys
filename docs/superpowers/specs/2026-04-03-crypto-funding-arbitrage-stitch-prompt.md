# Stitch Prompt: Crypto Funding Arbitrage Trading Console

请为我生成一个“中文 Web 端虚拟币量化交易系统”的高保真产品原型，面向个人自营交易者。产品定位是 `Binance 单所现货-永续对冲资金费率套利系统`，强调 `24/7 全自动执行`、`高可靠风控`、`友好但专业的交易指挥台`、`历史回测` 与 `策略模型扩展`。

## 产品设定

- 产品名：`Funding Command`
- 用户：个人自营量化交易者
- 目标：在一个统一控制台内完成机会扫描、持仓监控、风险控制、回测分析、模型管理与审计追踪
- 模式：支持 `Paper Trading` 和 `Live Trading`
- 重要要求：必须在视觉上强区分仿真盘与实盘，避免误操作
- 风格关键词：专业、冷静、可信、清晰、可操作、非花哨、非币圈赌场风

## 视觉方向

- 整体风格不要做成霓虹赛博朋克，也不要做成普通后台模板
- 主色建议：深海军蓝、石墨灰、青绿色点缀
- 辅助风险色：黄色用于预警，橙色用于限制，红色用于熔断或高危
- 背景不要纯白平铺，可以使用非常轻的深浅层次面、微弱网格或数据纹理，营造专业交易氛围
- 字体风格要现代、专业、有数字终端感，但仍保持中文可读性
- 图表要有高级金融终端感，信息密度高但层级清楚
- 通过卡片、数据表、标签、抽屉、分段控件、状态条、时间线构成界面

## 设计原则

- 桌面端优先，同时兼顾平板宽度
- 首屏 10 秒内必须让用户看懂系统是否健康、是否允许开仓、当前是否有高质量机会
- 所有高风险操作都要有明显确认与状态反馈
- 强调 glanceable dashboard：关键指标大、清楚、对比鲜明
- 不要堆砌花哨动效，只使用少量有意义的状态过渡、面板刷新、告警闪烁和抽屉展开动画
- 保证颜色对比、数字可读性、中文信息密度和可访问性

## 需要生成的页面

请生成以下 7 个页面，并保持统一设计系统、统一组件语言与统一状态表达：

1. 总览指挥台
2. 机会扫描页
3. 持仓监控页
4. 风控中心
5. 回测实验室
6. 模型工作台
7. 审计与日志中心

## 页面 1：总览指挥台

这是核心首页，采用“交易指挥台”布局，不是营销首页。

页面结构：

- 顶部全局状态条
  - 当前模式：Paper / Live
  - 交易所连接状态
  - 策略运行状态
  - 是否允许新开仓
  - 最近一次风险动作
  - 当前时间与下次 funding 倒计时

- 左上：账户健康主卡
  - 总权益
  - 可用余额
  - 保证金率
  - 净敞口
  - 今日 PnL
  - 累计 PnL
  - 资金利用率

- 右上：风控状态卡组
  - 风险等级
  - 限制开仓状态
  - 熔断状态
  - 告警数量
  - 数据延迟
  - 系统健康度

- 中部主区域：机会扫描榜单
  - Top opportunities 表格
  - 字段：交易对、资金费率、预估净收益、手续费侵蚀、流动性、建议仓位、白名单状态、风险标签、推荐等级
  - 每行支持“查看详情”与“加入观察”
  - 支持排序、筛选和快速标签切换

- 中下：持仓与对冲面板
  - 当前持仓卡片列表
  - 每个卡片展示现货腿、永续腿、对冲偏离、持仓时长、下一 funding 窗口、未实现 PnL
  - 高风险持仓要有明显视觉提示

- 右侧边栏：实时风险和事件时间线
  - 最新告警
  - 异常恢复
  - 风控动作
  - 配置变更

## 组件与状态要求

- 使用一致的设计系统、颜色 token、间距系统、按钮样式、卡片体系和图表语言
- 使用 mock data 填充所有页面
- 覆盖以下状态：
  - 加载中
  - 无数据
  - 无机会
  - 异常断流
  - 熔断中
  - 只减仓模式
  - 权限确认弹窗
- 关键操作要有 toast、横幅提示或状态条反馈

## 文案与信息表达

- 语言全部使用简体中文
- 文案风格专业但不冰冷，避免堆砌币圈黑话
- 告警文案必须包含：
  - 发生了什么
  - 影响什么
  - 系统已做什么
  - 用户可以做什么

## 输出要求

- 输出完整高保真 Web 原型
- 保持跨页面一致的设计系统
- 组件命名清晰，便于后续前端映射
- 优先生成桌面端复杂信息架构
- 确保界面既像“专业交易终端”，又比传统量化后台更友好、更易读
